✦ Resistor color code

The question I started with: how does a potentiometer encode the degrees of a servo motor? Before getting there, we had to learn to read our resistors.

What is the difference between the blue resistor and the light brown one?

  • Light brown: the metal band (silver or gold) sits at one end. That end is the tolerance, so I start reading from the other side.
  • Blue: it begins with the yellow band.

✦ In-class attempt: Hello, world over serial

  • USB stands for Universal Serial Bus.
  • /* */ and // are comments. They are for humans and are greyed out for the compiler. Comments help me understand code that an agent or somebody else wrote.
  • To receive the message, we need to start serial communication at a defined speed, here a 9600 baud rate.
  • The baud rate in the code and in the serial monitor needs to be the same.
  • 9600 is the common default. 115200 is the standard when communicating with the web.
  • Without a delay line, the code runs as fast as it can. Taking out the serial print makes it run faster too.

✦ Variables, voltage and the blink sketch

  • In this case the variable is 13. It is the pin number, not the LED itself. When the LED is on D12, the variable is 12.
  • LOW and HIGH refer to voltage from 0 to 5V, because 5V is the maximum an Arduino can provide.
  • 2.5V is the split line: everything below is LOW, everything above is HIGH.
  • Still wondering: how does an LED work? Electrons jump, and that becomes light.

✦ Laser cutter: digital fabrication

2D → 3D → joining technique

  1. Finger joint (tab and slots). Only if you have no choice.
  2. Mortise and tenon. Usually very strong, and allows a free edge.
  3. Tusk tenon / pinned joints.
  4. Snap-fit joints. Designed properly, they can flex.
  5. Slot hook & T.
  6. Fastener & hardware joints / captive nut joint.

✦ Rainbow Pak-Man

An interactive exploration game inspired by white balance. A Pak-Man on screen is connected to a physical Arduino RGB LED. Moving through a dark maze adjusts color temperature and tint, which changes both the on-screen color and the LED. Hidden treasures gradually appear within the beam.

The project turns color mixing and white balance into a playful experience that bridges the screen and the physical world.

Components: Arduino Uno, breadboard, 220Ω resistors, red / green / blue LEDs, wires.

How it works

  1. 1Web gamePak-Man moves through the maze
  2. 2Map position → colortemperature + tint → R, G, B
  3. 3Serial commandC,r,g,b or B,r,g,b
  4. 4Arduino parseschecks format, clamps 0–255
  5. 5RGB LEDPWM on pins 9 / 10 / 11

Step 1 · Original code tests

  • Fading LED: a counter i runs 0→763 in three phases. In each phase one channel goes down by 1 while the next goes up by 1 (red→green→blue→red), then the counter resets.
  • analogWrite sends the 0–255 values to pins 9, 10 and 11. wait = 5ms sets the fade speed.

Step 2 · Circuit arrangement

Step 3 · Controlled by the serial monitor

  • Commands are <colorCode><colorVal>: r, g or b, then a number from 0 to 255.
  • r0 turns red off, g127 sets green to half and b64 sets blue to a quarter.
  • The Arduino reads the serial bytes into a string, takes the first character as the channel and converts the rest with atoi.

Step 4 · Concept: white balance → Pak-Man

The first idea came from how white balance works. To make the interaction more engaging, I turned it into Pak-Man-style gameplay.

Step 5 · Diffuser iteration

A diffuser scatters direct, concentrated light in many directions, using translucent materials or textured surfaces. This makes the light source look bigger and reduces harsh shadows and glare. I tried different ways to diffuse the light.

Step 6 · Upgraded code

// website → Arduino, one line per command
C,255,180,90   // set color
B,255,180,90   // set color + blink 3 times

// Arduino → website
READY,WBPM1    // handshake on boot
OK,r,g,b       // command accepted
ERR,FORMAT | ERR,COMMAND | ERR,TOO_LONG
  • Protocol: commands arrive line by line (\n) into a 40-character buffer and are parsed with sscanf("%c,%d,%d,%d").
  • Handshake: the website waits for READY before it reports that it is synced.
  • Red calibration: the red channel is scaled by 0.36 before it is written to the pin.
  • Non-blocking blink: the code uses millis() instead of delay(). It toggles every 120ms, and 6 toggles make 3 flashes. That way the serial input is never blocked.
